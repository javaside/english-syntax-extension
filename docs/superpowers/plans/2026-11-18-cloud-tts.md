# 硅基流动云端朗读 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 双端朗读接入可选云端语音源(OpenAI 兼容 `/v1/audio/speech`),默认关、失败回落本地、语义与现状一致。

**Architecture:** Chrome: content 每页一个 `CloudSpeaker` 单例 → `TTS_SYNTHESIZE` 消息 → SW fetch(mp3) → `TTS_AUDIO` → Audio 播放;IDEA: `CloudSpeechSpeaker`(speak 即返,后台协程 wav+Clip,懒读 PasswordSafe)包装本地兜底。spec 四项 builder-check 裁决(单例/显式手势本地/不阻塞桥泵/懒读)为硬约束。

**Tech Stack:** TypeScript(MV3 SW fetch + content Audio)、Kotlin(OkHttp+javax.sound.sampled)、vitest/Playwright/Gradle。

**Spec:** `docs/superpowers/specs/2026-11-18-cloud-tts-design.md`(含四项裁决,执行者必读)

## Global Constraints

- **Chrome 协议四处同步**(protocol.ts 类型/SW 路由/isRuntimeResponse case/入站拒绝列表)——TTS_SYNTHESIZE 是 content-only 发送方,拒绝列表必须同步;漏一处 = 既知事故模式。
- apiKey 只存 SW 侧(chrome.storage.local `tts-source`)/IDEA PasswordSafe,**永不下发 content/桥**。快照只带 `tts:{enabled:boolean}`。
- 未配置/禁用时行为与 1.7.0 逐字节一致;云端任何失败回落本地,双双失败才报错。
- 提交中文主题;worktree `feature/cloud-tts`;门禁:chrome-plugin 全套 + intellij npm/gradle。

## Review Focus

1. **跨块同时出声**(裁决 1 的反面) → Task 2:E2E 断言两块连点只有一路 fetch/一路音频。
2. **在途请求作废**(点停后晚到 TTS_AUDIO 不得出声) → Task 2 单测(requestId/代际计数)。
3. **入站伪造 TTS_SYNTHESIZE 直达 SW** → Task 1:页面路由拒绝列表 case。
4. **IDEA 桥泵阻塞**(断网 5s 停摆) → Task 4:测试断言 speak 立即返回(fake 慢 OkHttp,speak 返回 <100ms)。
5. **云端失败回落本地出声**(不出 TTS_ERROR) → Task 2/4 各一条回落断言。
