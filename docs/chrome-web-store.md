## 单一用途说明

> 本扩展的单一用途是：把网页中的英文段落，按句子成分拆解并对照显示中文释义，帮助中文母语者理解英文句子结构。

商店政策要求扩展有且只有一个窄用途。上面这句直接填进「单一用途」字段。

## 商品详情

**名称**：英语句法伴读（≤ 45 字符）

**简介**（≤ 132 字符，即 manifest 的 `description`）：

> 按句子成分对齐英文结构与中文翻译。

**详细描述**：

```
把网页里读不懂的英文长句，拆成看得懂的结构。

选中或点开一段英文，扩展会把它就地替换成学习卡片：每个句子成分（主语、谓语、
定语从句、并列分句……）标出角色、配上颜色，英文原文与中文释义三行对齐。点任
意一个成分，还能展开它的详细语法解析。

■ 用你自己的模型
不内置任何模型服务。你可以填本机运行的 Ollama（数据完全不出电脑），也可以填
DeepSeek、OpenAI 或任何兼容 /chat/completions 的接口。多套配置可随时切换。

■ 边生成边显示
段落解析是流式的，成分逐个出现，不必干等整段跑完。

■ 解析会被缓存
同一句话只解析一次，跨页面、跨会话复用。缓存可导出分享，也可随时清空。没有配
置模型时进入纯缓存模式，仍能显示已缓存的解析。

■ 解析不对可以纠正
对某句的拆解不满意，写一句说明让它重新解析，结果按你的反馈单独缓存。

■ 隐私
不收集任何数据，开发者收不到你的任何信息——没有服务器，也没有统计代码。API
Key 只存在你的浏览器本地，网页脚本读不到。只有你主动触发解析时，待解析的句子
才会发往你自己配置的那个接口。

开源项目，代码与更新日志：
https://github.com/javaside/english-syntax-extension
```

**类别**：教育（Education）
**语言**：中文（简体）

## 权限说明（审核会逐条问）

| 权限           | 填写内容                                                                                                                                                              |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `activeTab`    | 用户点击扩展图标、使用右键菜单或快捷键时，读取当前页面的英文段落文本以进行句法解析。不在后台访问页面。                                                                |
| `scripting`    | 把解析后的学习卡片注入当前页面，替换原段落显示。                                                                                                                      |
| `storage`      | 在本地保存用户自己填写的模型接口配置与解析缓存。不上传。                                                                                                              |
| `contextMenus` | 提供「解析选中文本」与「解析此区域」两个右键菜单项。                                                                                                                  |
| 主机权限       | **声明为可选**（`optional_host_permissions`），默认不申请。仅当用户在设置页保存模型接口地址时，针对该地址按需申请。用途是把待解析的句子发送到用户自己指定的模型服务。 |
| 远程代码       | **否**。全部逻辑随安装包分发，不加载也不执行任何远程代码：不做动态求值、不构造动态函数、不注入远程脚本。                                                              |

> 审核最可能追问的是 `https://*/*` 这一条。要点：它在 `optional_host_permissions` 里，**不是常驻权限**，用户不填模型地址就永远不会被申请；之所以是通配符，是因为模型接口地址由用户自行填写，无法预先枚举。

## 数据用途声明

后台会让你勾选收集了哪些数据类别，并做三项承诺。按实际情况：

- **个人身份信息 / 健康 / 财务 / 个人通讯 / 位置 / 网页浏览记录**：均**不收集**。
- **用户活动**：不收集。
- **网站内容**：**需要勾选「正在处理」**。用户主动触发时，被解析的段落文本会发送到**用户自己配置的**接口。开发者不接收、不存储这些内容。
- **身份验证信息**：API Key 存在本地并随请求发往用户配置的接口。**开发者不接收**。若后台要求勾选，据实说明其仅在用户设备与用户指定的服务之间传递。

三项承诺（都可以如实勾选「是」）：

- 不将数据出售或转让给第三方（超出核准用途）
- 不将数据用于与单一用途无关的目的
- 不将数据用于判定信用状况或放贷
